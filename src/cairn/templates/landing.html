One address. Every agent connects to it.

cairn runs in one place, so nothing is installed on each machine. Give an agent this server's address, and your browser opens once to approve it. You choose which projects it reaches, and whether it may write there or only read.

What cairn refuses to save

Memory tools turn notes into tidy pages. The failures that matter are quiet ones, so cairn checks every page against its notes before it saves it.

A page that lost a fact
A version, a flag or a line of code in a note the page draws on is on the page, or is listed as left out.
A claim its source does not hold
A number, a flag or a path in a claim is in the lines that claim cites.
A claim without a source
Every claim cites the lines behind it, and you can open them.

A page that fails is rejected, and its last good version stays. Each claim is a passage copied word for word from a note. When the operator connects a model, it only chooses the order of a page's claims and folds repeated ones. cairn writes every claim from the note's own text, and the page says which model arranged it.

On your own machine

One container: the same software on your disk and your network, with no plans and no plan caps.

git clone https://github.com/macayaven/cairn
cd cairn/deploy
echo 'COMPOSE_FILE=compose.local.yaml' > .env
docker compose up -d --build

Then make a key and sign in. The repository's README has each step, and Run it yourself has backups and upgrades.

What happens to what you write

Keys, sessions and agents' tokens are stored only as digests. By default a guard refuses a note that holds a secret in a shape it recognises, such as a provider's API key or a private key, before any of it is stored; a password written in plain words is not recognised. Each project is an access boundary, and a connection limited to some projects cannot see that the others exist. Security and privacy say exactly what is kept, where, and for how long.
