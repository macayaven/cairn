# Slack's apps, Web API and Events API: what cairn relies on

Checked against Slack's own documentation on 18 November 2026. These notes hold the behaviour of Slack that cairn's test contract relies on. Slack's live behaviour is still to be confirmed with a workspace install.

## App setup

An administrator can create an app from pasted JSON or YAML in Slack's **Create New App → From an app manifest** flow. Slack also documents a link to the same creation flow: `https://api.slack.com/apps?new_app=1&manifest_json=<encoded JSON>`, or the corresponding `manifest_yaml` parameter, with the complete manifest percent-encoded before it is added to the URL. cairn gives a manifest to copy beside the link, and neither holds the signing secret or the bot token. [Configure apps with manifests](https://docs.slack.dev/app-manifests/configuring-apps-with-app-manifests/)

The JSON manifest uses `display_information.name`, `features.bot_user.display_name`, `features.slash_commands`, `features.shortcuts`, `oauth_config.scopes.bot`, `settings.event_subscriptions` and `settings.interactivity`. Each slash command has `command`, `description` and a `url` for a conventional public HTTPS install. The command starts with `/` and is at most 32 characters. A message shortcut uses `type: "message"` and requires `name`, `description` and `callback_id`, of at most 24, 150 and 255 characters. An app can have five global shortcuts and five message shortcuts. `settings.event_subscriptions.request_url` and `settings.interactivity.request_url` are the HTTPS receivers for events and interactions. Slack explicitly requires **manual event URL verification** when the manifest sets the event URL. [Manifest field reference](https://docs.slack.dev/reference/app-manifest/)

Slack shows the signing secret in the app administration panel under **Basic Info**. Under **OAuth & Permissions** the app is installed to the workspace, and the **Bot User OAuth Token** is then in **OAuth Tokens**. Workspace policy can require an administrator's approval. A user OAuth token and a signing secret serve other roles than the bot token. The signed challenge is the point at which cairn can confirm the receiver works with Slack. So the set-up runs: create and install the app, enter its two credentials into cairn, then have Slack verify the event URL. The order of Slack's console is still to be confirmed on a live synthetic install. [Signing secret](https://docs.slack.dev/authentication/verifying-requests-from-slack/) · [Find a bot token after installation](https://docs.slack.dev/apis/web-api/using-web-api-with-postman/) · [Single-workspace distribution and approval](https://docs.slack.dev/app-management/distribution/#undistributed-apps)

`auth.test` takes a token and returns its workspace and user identity. The documented success response includes `url`, `team`, `user`, `team_id` and `user_id`. It includes `bot_id` for a bot token and may include `enterprise_id`. A call's outcome is read from its JSON as well as from its HTTP status. The documented response holds no proof of the signing secret or of the app's id. So checking the token, verifying a signed callback and binding the provider's `api_app_id` to the install are three distinct checks. [auth.test](https://docs.slack.dev/reference/methods/auth.test/) · [Events envelope](https://docs.slack.dev/apis/events-api/#callback-field)

Slack's App Home offers the bot's direct conversation through the Messages tab. People can write to the bot when `features.app_home.messages_tab_enabled` is true and `features.app_home.messages_tab_read_only_enabled` is false. The same `chat:write` and `im:history` permissions and `message.im` delivery cover this surface. [App Home Messages tab](https://docs.slack.dev/surfaces/app-home/#using-the-messages-tab) · [Manifest fields](https://docs.slack.dev/reference/app-manifest/)

## Permission boundaries

- `commands` enables slash commands and shortcuts. `chat:write` is the bot scope for `chat.postMessage` and `chat.postEphemeral`. `users:read` covers `users.info`, for display names and the author's identity. cairn asks for no `users:read.email`, as it has no use for the email field. [commands](https://docs.slack.dev/reference/scopes/commands/) · [chat.postMessage](https://docs.slack.dev/reference/methods/chat.postMessage/) · [chat.postEphemeral](https://docs.slack.dev/reference/methods/chat.postEphemeral/) · [users.info](https://docs.slack.dev/reference/methods/users.info/)
- Slack delivers `message.im` with `im:history`. Commands and message shortcuts alone need no such scope. Keeping direct messages means saying during set-up that the app has the direct-message history permission, and acting only on events for messages deliberately sent to the bot. Retrieving a conversation's history is a separate behaviour. `app_mentions:read` supports mention events and does not replace the direct-message permission. [message.im](https://docs.slack.dev/reference/events/message.im/) · [app_mention](https://docs.slack.dev/reference/events/app_mention/)
- A message shortcut brings the selected message in its payload. Filing that one message needs no `conversations.history` or `conversations.replies` call. History scopes for conversations, following threads, reactions, link unfurls and collecting attachments are outside this contract. Slack applies an enhanced Marketplace review when an app asks for broad access, including `*:history`, search, files or canvases. [Shortcut payload](https://docs.slack.dev/reference/interaction-payloads/shortcuts-interaction-payload/) · [Marketplace review criteria](https://docs.slack.dev/slack-marketplace/slack-marketplace-app-guidelines-and-requirements/)
- In Slack Connect, members of the workspace where the app is installed can invoke its slash commands and message actions. A shortcut's top-level `user` is who invoked it, and `message.user` is the message's author when there is one. Owning the install, or its `team` in the payload, does not establish the author's affiliation. Slack documents telling an external author by `users.info`, from `team_id` and `is_stranger` together. cairn files a message only on evidence that its author is local, and refuses an identity that is missing or unclear. Recognising a conversation shared with another organisation takes the documented flag `is_ext_shared` on the conversation's object; the event envelope has its own `is_ext_shared_channel`. A conversation's prefix cannot tell whether it is shared or private. [Shortcut payload](https://docs.slack.dev/reference/interaction-payloads/shortcuts-interaction-payload/) · [Slack Connect](https://docs.slack.dev/apis/slack-connect/) · [Events envelope](https://docs.slack.dev/apis/events-api/#callback-field)

## Verifying and acknowledging inbound requests

The request headers are `X-Slack-Signature` and `X-Slack-Request-Timestamp`, and header names are case-insensitive. The signature is `v0=` followed by the HMAC-SHA256, in lowercase hexadecimal, of `v0:{timestamp}:{raw body}` under the app's signing secret, compared in constant time. It is computed over the body's original bytes, before a form or JSON is decoded. A timestamp more than five minutes from the server's clock is refused. The timestamp window limits how old a replay can be, so an effect that may repeat inside it is made idempotent. The old verification token is deprecated. The signing secret is chosen by the install's address, and the provider's workspace identity is checked after verification. [Signing and verification](https://docs.slack.dev/authentication/verifying-requests-from-slack/)

The Events API sends a JSON challenge, `type: "url_verification"`. Its signature is verified first, and the answer is the exact `challenge` in a 200 plain-text response; Slack also accepts form and JSON responses. An ordinary event has the outer `type: "event_callback"` and a nested `event`. The wrapper can include `team_id`, `api_app_id`, `event_id`, `event_time`, `authorizations`, `context_enterprise_id` and `is_ext_shared_channel`; which fields apply depends on the kind of install. `event_id` is globally unique, and handling it once per install also keeps to cairn's workspace scope. [URL verification](https://docs.slack.dev/reference/events/url_verification/) · [Events API](https://docs.slack.dev/apis/events-api/)

Slack expects a successful HTTP response to an event delivery within three seconds. Slack documents up to three ordinary retries: almost at once, then after one minute and after five. `x-slack-retry-num` is `1`, `2` or `3`. `x-slack-retry-reason` can be `http_timeout`, `too_many_redirects`, `connection_failed`, `ssl_error`, `http_error` or `unknown_error`. A non-200 response with `x-slack-no-retry: 1` stops the retries of the same delivery. Slash commands and actions have their own rules for acknowledging, and promise no Events API ids. The acknowledgement keeps within the deadline by waiting on no provider lookup and no backoff, and work that goes on after it needs the accepted effect, or the pending work, to be durable first. [Events retries](https://docs.slack.dev/apis/events-api/#retries) · [Handling interactions](https://docs.slack.dev/interactivity/handling-user-interaction/)

`app_uninstalled` and `tokens_revoked` both come without any added OAuth scope, and they can arrive in either order. Slack sends the complete uninstall when the last user and bot tokens are gone. `event.tokens.bot` and `event.tokens.oauth` hold the user ids whose tokens were revoked. These fields let cairn tell the revocation of its own bot from a partial revocation of an unrelated user's token. Enough of the install's state is kept to make the clean-up idempotent in either order. [app_uninstalled](https://docs.slack.dev/reference/events/app_uninstalled/) · [tokens_revoked](https://docs.slack.dev/reference/events/tokens_revoked/)

## Commands, shortcuts and replies

A slash command is sent as a POST in `application/x-www-form-urlencoded`. Its documented fields include `team_id`, `channel_id`, `user_id`, `command`, `text`, `response_url` and `trigger_id`. A developer's slash command cannot run in a message thread. It is acknowledged within 3,000 milliseconds. Slack makes a command's response `ephemeral` by default; cairn sets it explicitly all the same, as it returns private search results and refusal details. [Slash commands](https://docs.slack.dev/interactivity/implementing-slash-commands/)

An interaction's POST carries a form field `payload` that holds JSON. A message shortcut gives `type: "message_action"`, a `callback_id`, `trigger_id`, `user`, `team`, `channel`, `message` and `response_url`. The selected message can give `message.ts`, `message.user` and `message.text`. A global shortcut has `type: "shortcut"` and gives neither the same message context nor a reply URL. A modal that confirms the action can show exactly what will be filed and where. Opening a modal takes a trigger used within three seconds, and only once. `views.open` documents `expired_trigger_id` and `exchanged_trigger_id`. [Shortcut payload](https://docs.slack.dev/reference/interaction-payloads/shortcuts-interaction-payload/) · [Implementing shortcuts](https://docs.slack.dev/interactivity/implementing-shortcuts/) · [views.open](https://docs.slack.dev/reference/methods/views.open/)

Slack accepts up to five messages to a `response_url` within 30 minutes. This HTTPS address gives a limited authority to post for the action that started it, including a way back around the usual permission to post in a conversation. So it is kept out of logs, out of what a person sees and out of stored notes, taken only from a verified incoming payload, and its destination held to the provider's. GovSlack uses another domain. A private reply through this address is not `chat.postEphemeral`, which expects both `channel` and `user` and can fail with `user_not_in_channel`. [Responding to interactions](https://docs.slack.dev/interactivity/handling-user-interaction/) · [chat.postEphemeral](https://docs.slack.dev/reference/methods/chat.postEphemeral/)

A message holds at most 50 blocks; modals and Home tabs hold 100. A section's text is at most 3,000 characters. A message carries a meaningful top-level `text` as its fallback. Slack's `mrkdwn` control characters `&`, `<` and `>` are escaped as `&amp;`, `&lt;` and `&gt;` when they stand for ordinary text. Once `verbatim` is true, a text object's automatic links and mention transformation are suppressed. Explicit formatting still works, so untrusted text is still escaped. Plain-text objects serve where formatting adds nothing. [Block limits](https://docs.slack.dev/reference/block-kit/blocks/) · [Section text](https://docs.slack.dev/reference/block-kit/blocks/section-block/) · [Text objects](https://docs.slack.dev/reference/block-kit/composition-objects/text-object/) · [Text formatting](https://docs.slack.dev/messaging/formatting-message-text/)

`chat.getPermalink` is Slack's source of a message's canonical URL, from the conversation's id and the timestamp. It needs a Slack token and lists no extra scope. Its examples show `/archives/{channel}/p{timestamp without the dot}` and, for a reply in a thread, a query with `thread_ts` for the thread's first message and `cid` for the conversation. cairn builds the link itself from these examples, with the Slack workspace's origin as positively verified and the timestamps as strings. Links for real top-level and threaded messages are still to be checked in the trial. [chat.getPermalink](https://docs.slack.dev/reference/methods/chat.getPermalink/)

## Outbound rate limits

Slack measures the Web API's rate groups per method, app and workspace. Tiers 1 to 4 allow at least 1, 20, 50 and 100 calls a minute. HTTP 429 carries `Retry-After` in seconds. `chat.postMessage` generally allows one message a second in each conversation, and has a separate limit for the workspace. Retries are bounded, and a wait the provider asks for is honoured outside the deadline for acknowledging an inbound request. [Rate limits](https://docs.slack.dev/apis/web-api/rate-limits/) · [Message posting limits](https://docs.slack.dev/reference/methods/chat.postMessage/)

Slack keeps Tier 3 on `conversations.history` and `conversations.replies` for Marketplace apps and genuine internal apps a customer built. The change of May 2025 applies 1 call a minute and a limit of 15 items to new commercially distributed apps outside the Marketplace, and to new installs of them. The live method reference is the source for any particular pagination argument: the `conversations.history` reference and the changelog describe the page size differently. Filing a selected message depends on neither history method. [May rate change](https://docs.slack.dev/changelog/2025/05/29/rate-limit-changes-for-non-marketplace-apps/) · [June clarification](https://docs.slack.dev/changelog/2025/06/03/rate-limits-clarity/) · [History](https://docs.slack.dev/reference/methods/conversations.history/) · [Replies](https://docs.slack.dev/reference/methods/conversations.replies/)

## Distribution and data lifecycle

Slack documents a single-workspace, undistributed configuration for an app that the customer's own organisation runs. Slack's clarification of October 2025 places genuine internal apps outside the API Terms' section on external distribution. A self-hosted install that its owner runs fits that technical model when the customer creates the app and owns all the processing. A hosted cairn receives the customer's Slack data, and separate app ids or manifests the customer owns do not establish an exception for it. For an app offered externally, the API Terms require express authorisation from the installing organisation, and limit processing and retention to the minimum needed. They bar training an LLM, bulk export without separate authorisation, and using one organisation's data to benefit another. Commercial distribution also covers custom templates tied to paid products or features, under Slack's stated condition for an app and service made solely for a single third party. Slack's classification is needed before the hosted server switches Slack on. [Slack app distribution](https://docs.slack.dev/app-management/distribution/) · [API Terms, effective 10 October 2025](https://slack.com/terms-of-service/api) · [13 October clarification](https://docs.slack.dev/changelog/2025/10/13/api-terms-update/)

A hosted pilot in a tester's workspace needs a representative with authority for the installing organisation to approve the named cairn operator's use, processing and storage of Slack API data. Slack's terms name those three activities and require a user agreement and a privacy policy people can reach; they leave the form of the approval open. A separate recorded approval describes the selected messages and direct inputs, the author and source metadata, the purpose and destinations, the operator and any subprocessors, where processing happens, the private replies, retention and removal including backups, and how to revoke access. Installing a Slack app grants its token's scopes. The approval of the external handling is recorded beside it, and the distribution class settled with Slack, before Slack is switched on there. [API Terms, third-party distribution and data use](https://slack.com/terms-of-service/api) · [Workspace app approvals](https://slack.com/help/articles/222386767-Manage-app-approval-for-your-workspace/) · [Developer Policy](https://docs.slack.dev/developer-policy/)

Slack's Developer Policy requires appropriate consent, strong encryption of the data stored and served, a clear privacy policy, and deletion of the associated data within 14 business days when the user deletes the application or it is discontinued. Slack API data includes messages and their metadata even when a selected message becomes a note in cairn, and no exception for selected notes kept word for word was established. So removing an install needs provenance and a bounded erasure, copies in evidence and search indexes included, and a rule for derived material and backups is to be agreed before release. Whether deleting one message upstream brings a separate duty to delete it automatically is not settled by this check. The API Terms' restrictions on persistent copies for the Data Access and Real-Time Search APIs are specific to those APIs. [Developer Policy, effective 10 December 2024](https://docs.slack.dev/developer-policy/) · [API Terms](https://slack.com/terms-of-service/api) · [Uninstall event](https://docs.slack.dev/reference/events/app_uninstalled/)

## Potential later transports and features

Socket Mode can receive events and interactions through `apps.connections.open` and an app-level token with `connections:write`. Each envelope is acknowledged by its `envelope_id`. Slack supports up to ten connections at once, and keeps Socket Mode apps out of its public Marketplace for now. A cairn on loopback has no public HTTP callback; Socket Mode is a path apart from the first install, which is HTTPS only. [Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/)

Slack OAuth v2 starts at `https://slack.com/oauth/v2/authorize` with `client_id`, the scopes asked for, a matching redirect and a validated state. The code expires in ten minutes. `oauth.v2.access` exchanges it and can name the bot user, the workspace and the enterprise. An organisation's install can have an enterprise and no `team` at the workspace's level. Supporting these needs an explicit model of identity and install. Token rotation is a separate opt-in, with tokens of 12 hours and a refresh exchange, and Slack says it cannot be switched off once enabled. [OAuth installation](https://docs.slack.dev/authentication/installing-with-oauth/) · [OAuth response](https://docs.slack.dev/reference/methods/oauth.v2.access/) · [Token rotation](https://docs.slack.dev/authentication/using-token-rotation/)

Slack's surface for agents uses `assistant:write` and events including `assistant_thread_started`. The provider describes its capabilities and a migration to `agents.sessions.setStatus`. This API is a later option for cairn's commands and shortcuts, which call no model. A later release that adopts it has the account's eligibility, the current limits and the Marketplace's obligations to confirm. [Developing agents](https://docs.slack.dev/ai/developing-agents/) · [Agent messaging update](https://docs.slack.dev/changelog/2026/08/20/agent-updates/)
